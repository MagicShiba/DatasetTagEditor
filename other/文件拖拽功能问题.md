"emitDropEvents": true 
启用时会影响浏览器内部自身的拖放功能，导致拖放无效。
但若不添加，则外部向内部拖放时无法获取文件路径。

目前没有好的解决办法。

目前一些探索：
Neutralino Windows 原生 DnD 只 RegisterDragDrop(m_window) 主窗口（webview.h:1409），但 WebView2 windowed 模式下内部子 HWND（Chrome_WidgetWin）覆盖整个客户区，OS 把拖放事件发给鼠标下方子窗口 → 主窗口 DropTarget 在内容区收不到 → filesDropped 不触发、显示禁止光标。Tauri/wry 解法是 EnumChildWindows 逐子窗口 RevokeDragDrop + RegisterDragDrop（MicrosoftEdge/WebView2Feedback #2907、tauri#8532）；当前 Neutralino main 分支无 EnumChildWindows。


在 emitDropEvents 块中加入 EnumChildWindows 注册
    // 修复 WebView2 子窗口拦截 OLE 拖放的问题：
    // WebView2 会在宿主窗口内创建多个子窗口（Chrome_WidgetWin 等）覆盖整个客户区，
    // OLE 拖放事件只投递给光标下方的窗口，而主窗口的 DropTarget 收不到事件。
    // 因此需要枚举所有子窗口，将同一个 DropTarget 注册到每个子窗口上。
    EnumChildWindows(m_window, [](HWND hwnd, LPARAM lParam) -> BOOL {
      RevokeDragDrop(hwnd);
      RegisterDragDrop(hwnd, reinterpret_cast<IDropTarget *>(lParam));
      return TRUE;
    }, (LPARAM)dropTarget.Get());
